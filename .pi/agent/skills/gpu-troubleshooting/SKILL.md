# GPU troubleshooting

Load this skill whenever the trigger matches; the rules below are binding for that task.

## nvidia-powerd

**nvidia-powerd = D-STATE DEADLOCK TRIGGER:** ASUS platform-profile switch → Performance makes asusd start nvidia-powerd.service (unit itself disabled; supergfxd GONE — not installed). powerd opens /dev/nvidiactl → dGPU runtime resume → RmInitAdapter/kgspInitRm (GSP boot) hangs holding rmapi rw-semaphore write lock → rm_acpi_nvpcf_notify (kacpi_notify, Dynamic Boost), nvidia-smi, powerd all block D-state forever (kill -9 useless); shutdown SIGTERM times out → forced poweroff. Driver nvidia 610.57.04 open module, RTX 4060 Max-Q (10de:28a0), GPU 0000:c4:00.0. ASUS SBIOS NVPCF interface defective: NVRM PlatformRequestHandler NV_ERR_INVALID_DATA asserts every boot. **FIX APPLIED: `systemctl mask nvidia-powerd.service`** (symlink → /dev/null; reversible `systemctl unmask`; cost = no Dynamic Boost, already broken). If the hang ever recurs AFTER masking, the trigger is not powerd — re-investigate who opened /dev/nvidia*.

## amdgpu TTM

**amdgpu TTM NULL-deref → full freeze after hibernate resume:** kernel `BUG: NULL pointer dereference` in `ttm_lru_bulk_move_del` during a VRAM buffer move corrupts the TTM LRU spinlock → every GPU consumer spins forever (104 soft-lockups). Trigger = AGS gjs normal GPU work ~14 min after S4 wake. NOT NVIDIA/thermal/OOM. Known-class amdgpu TTM LRU race, watch upstream. Full trace: /home/tinoy/context.md.

## Hybrid GPUs + dGPU wake

**Tablet-mode fold wakes the dGPU, kernel-side — there is no userspace waker to find.** Crossing the hinge threshold into tablet mode resumes `0000:c4:00.0` inside the same 50 ms sample that sees `SW_TABLET_MODE` flip, with NO process holding an `/dev/nvidia*` fd and no udev `power_supply`/`platform` uevent, no ACPI line and no NVRM line; the GPU then holds active and autosuspends on its own ~20 s later (measured: `sw 0->1` and `suspended->resuming` in one tick, `active` 2 s on, unfold 5 s later, `suspending` 17 s after that — 22.7 s added to `runtime_active_time`). UNFOLDING DOES NOT WAKE IT. The trigger is the firmware platform event that carries the tablet switch reaching the NVIDIA platform channel (`\_SB_.NPCF`, ACPI HID `NVDA0820`, platform device `NVDA0820:00`), the same ACPI notify path that logs `NVRM: rm_power_source_change_event` on an AC/DC toggle — handling it needs the GPU, so PCI runtime PM resumes it. `asusd`, udev, Hyprland and tinshell are all silent at the transition (tinshell only toggles widget visibility in-process). The DISCRIMINATOR is the fd holder: Vulkan ICD enumeration, the usual waker, always leaves a process holding `/dev/nvidia*`; a kernel-initiated resume leaves none. The in-kernel entry point is `nv_acpi_nvpcf_event`/`rm_acpi_notify` → `os_ref_dynamic_power` → `nv_pmops_runtime_resume`: the firmware notification tells the driver to re-read platform settings it owns (GPU temperature target, power limits), and reading them needs the device in D0. It costs ~20-25 s of D0 per event (issue #1300 measured a whole-laptop rise from a 9.2 W median to 15-19 W during the transient); the same channel fires periodically on other ASUS hybrid laptops and can cost ~20% of battery runtime (#860, #905, #1201). Community patches #1299 (defer+replay) and #1181 (drop) exist; neither is upstream.

**Which handler can and cannot be the culprit (615.71.09 source).** `rm_power_source_change_event` ALREADY dedupes: it keeps `static NvBool first_event_seen` / `static NvU32 last_event_val` and returns without entering PM runtime when the same value repeats consecutively — so an unchanged AC state cannot wake the GPU through the power-source path, and a real AC/DC alternation still does (legitimate: new limits). The two paths that ref dynamic power UNCONDITIONALLY are `rm_acpi_nvpcf_notify` (NPCF `0xC0` events) and `rm_acpi_notify` → `RmHandleGPSStatusChange` (GPS/D-notifier) — a tablet fold that leaves AC state untouched must be riding one of those. Patches to port for a local build: #1299 (defer the NPCF event while idle and replay it after the next resume — nothing is lost) and #1181's early-return guard on `RmHandleGPSStatusChange`/`rm_acpi_nvpcf_notify` (drops the event; the driver then never re-reads those settings). On Arch the build route is `nvidia-open-dkms` (extra; provides `nvidia-open`/`NVIDIA-MODULE`, conflicts with the prebuilt `nvidia-open`), patch applied in the PKGBUILD prepare step or the `/usr/src/nvidia-<ver>` tree, then `dkms install --force` — a package upgrade of the dkms package overwrites that tree, so keep the patch file and re-apply it. AC plug/unplug is the INTENDED case for this channel and behaves identically — one toggle measured +22.5 s of D0 — but there the driver genuinely has new firmware settings to read (AC and battery use different power limits), which is what distinguishes it from the tablet fold.

**Hybrid GPUs + dGPU wake:** AMD iGPU (display) + RTX 4060 Max-Q dGPU (runtime-suspended; `/sys/bus/pci/devices/0000:c4:00.0/power/runtime_status`, fine-grained D3). Waker = **Vulkan ICD enumeration** (GTK 4.16+ defaults to Vulkan on Wayland; Chromium/Electron enumerate too). EGL is NOT the waker. Fix = `VK_ICD_FILENAMES=radeon_icd.json` (+ Mesa EGL pin) in the tinshell-shell unit + `hl.env()` in hyprland.lua (session-wide; `hyprctl reload` applies live). The shell unit ALSO sets `GSK_RENDERER=gl`: under the Vulkan renderer, gtk4paintablesink's paintable comes up 0x0 after a player window close+reopen → video never binds → decoded frames pile up ~100MB/s → OOM. GL keeps the sink healthy. Launcher's prime-run button clears the pins (`env -u VK_ICD_FILENAMES -u __EGL_VENDOR_LIBRARY_FILENAMES prime-run <cmd>`) — required for the NVIDIA ICD.
